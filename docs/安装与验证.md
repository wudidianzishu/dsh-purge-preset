## 第一组：配置能否合成

```sh
dsh --dump-config --profile web
```

结果：

- 退出码 `0`
- 预设清单出现 `preset-purge`，与官方 4 个并列（`standard` / `ptc` / `minimal` / `cordis`）
- `complete: true` 落在 persona 段
- **无新增 warning**（安装前该 profile 有 7 条历史告警，与本 preset 无关）

这一步只证明"配置树能合成"，不证明运行效果。

## 第二组：会话真的用了这个 preset

dsh 的会话文件是**多帧 zstd**。单次解压只能得到第一帧（约 184 字节，只有会话头），必须按魔数 `28 B5 2F FD` 切帧逐帧解压再拼接。

```js
import fs from 'node:fs';
import zlib from 'node:zlib';

const buf = fs.readFileSync(sessionFile);
const MAGIC = Buffer.from([0x28, 0xb5, 0x2f, 0xfd]);
const offs = [];
let i = 0;
while ((i = buf.indexOf(MAGIC, i)) >= 0) { offs.push(i); i += 4; }

let text = '';
for (let k = 0; k < offs.length; k++) {
  const s = offs[k], e = k + 1 < offs.length ? offs[k + 1] : buf.length;
  try { text += zlib.zstdDecompressSync(buf.subarray(s, e)).toString('utf8'); } catch {}
}
```

解压后首行：

```json
{"type":"session","version":4,"agentPreset":"purge"}
```

`agentPreset` 的值即当前会话所用的 preset id，可直接证明切换生效。

## 第三组：系统提示词的归因

从会话日志中取出 `system/message` 事件，检查正文（实测 23,122 字符）：

| 检查项 | 实测 | 说明 |
|---|---|---|
| 破甲词出现次数 | 1 | 若同时存在其他注入来源，会出现 2 份 |
| `complete: true` 是否生效 | 是 | 第一方工具指导段（`<system-reminder>` / `Tools`）**0 处** |
| 工具是否仍在 | 是 | `request/header` 中工具齐全：`ask_user_question` `edit` `glob` `grep` `pwsh` `read` `present` `schedule_*` … |
| 工作目录 | 由上下文提供 | 正文结尾有 `Your working directory is <cwd>.` |

**结论**：`complete: true` 砍掉的是"工具说明书"，`tool schema` 走独立 wire 字段照常送达。工具可用性与 `complete` 无冲突。

## 复现建议

1. 装好后新建会话，让它做一件必须用工具的事（例如列目录）——这比问敏感问题更能检验 `complete: true` 是否伤到工具调用。
2. 想确认提示词内容，不要去猜：直接读会话日志里的 `system/message`。
3. 改动 `src/` 后重跑 `node src/build.mjs`，再用 `git diff --stat preset/cordis.patch.yml` 确认产物变化符合预期。

## 排错

| 现象 | 可能原因 |
|---|---|
| 模式选择器里没有「破甲模式」 | 追加位置不在顶层数组；或未重启；或 YAML 缩进错 |
| 启动直接失败，报 `unknown prompt variable` | 正文里出现了未注册的 `{{…}}` |
| 启动失败，日志 `EADDRINUSE` | 旧实例仍占用 3080 端口 |
| 切过去后工具变笨 | `complete: true` 移除了工具使用指导，需在 prefix 内自行补充 |
| 切过去后完全没人设 | 检查 `persona.prefix` 是否被子块覆盖 |
